ByteSavor UI 重构方案 v1

参考薄荷健康、Foodvisor、MyFitnessPal 等成熟模式，但保持 ByteSavor 的 B-Y-T-E Agent 主线。方案只动 UI 层，不动接口、状态和后端逻辑。

调研提炼

薄荷健康

强项是中文食物库、饮食/运动记录、体重管理和减脂方案。ByteSavor 可借鉴“记录入口近、营养数据清楚”，但不继承社区/商城/课程堆叠。

Foodvisor

强项是拍照/条码/语音/文本多入口，强调 5 秒记录和 AI 营养解读。ByteSavor 应把“拍照识别”变成第一主操作。

MyFitnessPal

新版 Today 把 Diary 作为首页，顶部展示 calories/macros/meals。ByteSavor 应把“今日任务闭环”作为首页，而不是普通功能宫格。

三种设计方向

A

薄荷式健康记录

三餐、热量、体重、营养优先。成熟但容易遮住 ByteSavor 的 Agent 差异化。

B

AI 主厨工作台（推荐）

首页围绕“拍照/输入 → 推荐 → 清单 → 反馈”。最贴合现有后端 B-Y-T-E 闭环。

C

菜谱探索社区

内容流更漂亮，但需要大量图片、社区和运营内容，和当前代码基础不匹配。

页面级改造

识别页

相机区域做成“扫描画布”，增加三阶段进度：上传、VLM 推理、人工校正。结果卡显示置信度条、新鲜度状态、编辑按钮。

健康看板

顶部改为一张营养总览卡，宏量营养用环形/条形组合；缺口列表按“需要补齐”排序，减少重复卡片。

探索页

修复缺失图标；从普通列表改为“筛选 chips + 紧凑菜谱卡”，突出时间、热量、目标标签。

详情页

重排为：菜名与匹配理由、元信息、食材、步骤、营养、反馈。购物清单按钮固定底部，减少长页迷路。

清单页

从按钮堆叠改为“采购任务页”：统计条、分组清单、勾选态、底部操作栏。保留复制/Markdown/分享/返回逻辑。

我的/设置

统一头像、健康分、目标和偏好标签；菜单用一致图标和行高，减少红色退出按钮的视觉压迫。

设计系统

视觉语言

  • 背景：浅雾绿/暖白，不继续偏奶油黄过重
  • 主色：健康绿 #22C55E，深墨绿用于 Hero
  • 辅助色：蛋白番茄红、碳水琥珀、AI 紫、信息蓝
  • 卡片圆角收敛到 16-20rpx，避免全站过圆

交互与动效

  • 页面进入：轻微 fade-up，避免过度弹跳
  • 主按钮：pressed scale 0.98
  • 识别进度：三段式 stepper + loading dots
  • 推荐出现：列表 stagger，不改变数据加载逻辑

否定审查

这套方案不能为了“漂亮”牺牲效率。首页不做营销英雄页，不加假数据，不加后端不支持的扫码、社区、商城、会员和真实三餐记录。健康建议保留免责声明边界，避免看起来像医疗诊断。

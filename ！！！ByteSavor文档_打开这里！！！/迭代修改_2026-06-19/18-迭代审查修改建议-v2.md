## P1-1：MemoryContext 的 conversation memory 没有真正接到 API 入口

### 证据

文件：

- `app/routers/agent.py:41-46`

当前代码：

```python
memory_context = await build_memory_context(
    db, user_id or None,
    previous_state=None,
    goal=goal,
)
```

`previous_state` 永远是 `None`。

虽然 `LangGraphAgent.run()` 内部会 `_load_previous_state(conversation_id)`，但 MemoryContext 已经在路由层提前构造完了，所以返回给前端的：

- `memory_context.conversation_memory.last_ingredients`
- `memory_context.conversation_memory.last_recipes`
- `memory_used`

不会体现上一轮对话。

### 影响

文档说“同一 conversation 第二轮能看到上一轮 ingredients 或 recipes”，但 API 层目前不成立。答辩时如果展示“Agent 记住上一轮”，容易被实际返回打脸。

### 修改要求

推荐改法：把 previous_state 读取前置到路由层，或把 MemoryContext 构造下沉到 runtime。二选一。

#### 方案 A：路由层前置读取，改动较小

给 `LangGraphAgent` 增加公开方法：

```python
async def get_previous_state(self, conversation_id: str) -> dict | None:
    return await self._load_previous_state(conversation_id)
```

然后在 `app/routers/agent.py` 中：

1. 先创建或取得 runtime。
2. 调 `previous_state = await runtime.get_previous_state(req.conversation_id)`。
3. 再 `build_memory_context(..., previous_state=previous_state, goal=goal)`。
4. 再调用 `runtime.run(..., memory_context=memory_context)`。

注意：当前代码是在构造 memory_context 后才取得 runtime，需要调整顺序。

#### 方案 B：runtime 内部构造，架构更干净

`LangGraphAgent.run()` 接收 `db/user_id/goal` 或一个 `memory_builder`，在 `_load_previous_state()` 后构造 MemoryContext。

这个方案更合理，但改动更大。短期建议选方案 A。

### 必补测试

新增测试：

测试逻辑：

2. 第二轮同一 `conversation_id` 调用“把刚才的菜生成购物清单”。
3. 断言 `memory_used` 或 `memory_context.conversation_memory.last_recipes` 包含“南瓜牛肉饭”。

## P1-2：`AgentRuntime._result()` 没有返回 `memory_context` / `memory_used`

当前 `_result()` 返回字段包含：

- `status`
- `conversation_id`
- `events`
- `errors`

但不包含：

- `memory_context`
- `memory_used`

路由层后面用：

```python
result["memory_context"] = memory_context
result["memory_used"] = build_memory_used(memory_context)
```

这会覆盖 runtime 过程中可能更新出来的记忆。

### 影响

```python
"memory_context": state.get("memory_context", {}),
"memory_used": state.get("memory_used", []),
```

并在 runtime 初始化或 final 前：

```python
if not state.get("memory_used"):
    state["memory_used"] = build_memory_used(state.get("memory_context", {}))
```

然后路由层不要无条件覆盖：

```python
result["memory_context"] = result.get("memory_context") or memory_context
result["memory_used"] = result.get("memory_used") or build_memory_used(result["memory_context"])
```

### 证据

文件：

当前 `_finish_run()`：

2. 再 evaluate_hard。
3. 再 append evaluation event。

这和我们文档里的 Loop Engineering 不一致。LangGraph runtime 是 `evaluator -> final`，普通 runtime 是 `final -> evaluation`。

### 影响

### 修改要求

```text

```

修改 `AgentRuntime._finish_run()`：

1. 先执行 `evaluate_hard(state)`。
2. append evaluation event。
3. 根据 evaluation 计算 status / termination_reason。
4. 最后 append final event。

```python
codes = {issue.get("code") for event in events for issue in event.get("issues", [])}

if "LOW_CONFIDENCE_INGREDIENT" in codes:
    prompts.append(...)

if "CORE_INGREDIENT_MISSED" in codes:
    prompts.append(...)

if "NEEDS_USER_CONFIRMATION" in codes or result.get("recipes"):
    prompts.append(...)
```

注意去重，不要同一个 code 生成多张重复卡片。

core_ingredients = state["intent"].get("ingredients") or state.get("core_ingredients") or []

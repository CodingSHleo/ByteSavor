# ByteSavor 偏好融合推荐、搜索与 AI 助手修复记录

日期：2026-06-21

背景：用户指出偏好不应该只存在个人资料里，而应该参与推荐、菜谱搜索和 AI 助手回答。否则系统只是在“有偏好字段”，没有真正使用偏好。

---

## 1. 推荐排序接入偏好

### 修改内容

文件：`app/services/decision.py`

新增偏好归一化：

- `清淡` / `少油` / `低油` -> `light`
- `香辣` / `麻辣` / `辣` -> `spicy`
- `高蛋白` / `蛋白` -> `high_protein`
- `低碳` / `低碳水` -> `low_carb`
- `素食` / `蔬菜` -> `vegetarian`
- `海鲜` / `鱼` / `虾` -> `seafood`

排序逻辑现在会在食材覆盖相同的情况下使用偏好：

1. 先满足用户现有食材。
2. 同等食材覆盖下，匹配偏好标签/菜品特色的菜排前。
3. 每道推荐 `_meta.preference_matches` 返回本菜命中的偏好。

### 新增回归测试

文件：`tests/test_decision.py`

新增：

```python
test_rank_uses_user_preferences_when_ingredient_coverage_is_equal
```

覆盖场景：

- 用户输入 `牛肉`
- 用户偏好 `清淡/少油`
- 候选有 `香辣牛肉` 和 `清炒牛肉`
- 结果必须优先 `清炒牛肉`
- `_meta.preference_matches` 必须包含 `light`

## 3. AI 助手接入偏好

### 修改内容

文件：`app/routers/assistant.py`

`/v1/assistant/chat` 现在支持可选登录用户上下文：

1. 通过 `get_optional_user` 获取当前用户。
2. 读取用户 profile。
3. 把 `goal` 和 `preferences` 传给 `app.services.assistant.chat()`。
4. 复用 `_parse_intent_regex()` 从用户文本中提取食材，并传入 prompt。

这样 DeepSeek prompt 会同时拿到：

- 用户当前输入；
- 当前食材；
- 用户目标；
- 用户偏好。

### 边界说明

AI 助手可以用 DeepSeek 生成自然语言建议，但主推荐仍遵守数据库候选和硬约束逻辑：

- 推荐接口不允许 LLM 编造不存在菜谱；
- LLM rerank 只能重排数据库候选；
- 没有 API key 时回退本地规则，系统不断链。

## 5. 后续建议

1. 把偏好展示到推荐卡片上，例如“匹配偏好：清淡/高蛋白”。
2. 偏好可以继续细分为：
   - 口味偏好；
   - 食材偏好；
   - 做法偏好；
   - 菜系偏好；
   - 忌口/不喜欢。
3. 后续 Eval 用例要加入：
   - 清淡用户不应首推重辣菜；
   - 高蛋白用户同等食材下优先高蛋白菜；
   - 不喜欢油腻用户应降低 oily/comfort_food 结果。

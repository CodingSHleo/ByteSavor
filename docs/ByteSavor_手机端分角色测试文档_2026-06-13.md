> 日期：2026-06-13

## 0. 重要修正

旧 `demo_tests/README.md` 里有一处历史预期已经过期：

```text
VLM 未配置 -> 降级 Mock
```

当前正确预期是：

```text
VLM 未配置或不可用 -> 返回 VLM_UNAVAILABLE / 明确错误，不允许返回固定 mock 食材冒充真实识别。
```

## 1. 测试前准备

### 1.1 手机端网络要求

手机和电脑必须在同一个局域网。

前端 API 地址不能是：

```text
http://127.0.0.1:8000
http://localhost:8000
```

手机上应该访问电脑局域网 IP，例如：

```text
http://192.168.x.x:8000
```

如果手机打开页面后一直显示“网络异常，请重试”，优先检查：

1. 手机和电脑是否同 Wi-Fi。
2. 后端是否用 `--host 0.0.0.0` 启动。
3. 手机端 API base URL 是否是电脑局域网 IP。
4. macOS 防火墙是否拦截 8000 端口。
5. 后端日志是否收到请求。

### 1.2 后端启动建议

```bash
cd ~/Desktop/bytesavor-backend
JWT_SECRET=test-review-secret ./venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 1.3 前端运行方式

如果是 H5：

```bash
cd ~/Desktop/bytesavor-backend/bsapp
npm run dev:h5 -- --host 0.0.0.0 --port 5174
```

如果是小程序真机调试：

1. 确认小程序可以请求局域网后端。
2. 如果平台限制 HTTP，需要配置开发模式或临时使用 H5 演示。
3. 真机调试时打开控制台，观察请求失败原因。

## 2. 测试角色划分

你分角色做测试是对的。ByteSavor 的功能不是单接口，而是围绕不同用户角色展开。

| 角色 | 测试目标 | 重点页面/功能 | 必须通过 |
|---|---|---|---|
| R1 新用户 | 验证首次进入、登录、画像、偏好设置 | 登录/注册、设置、首页 | 能登录，能保存偏好，首页不空白 |
| R2 做饭用户 | 验证“有什么食材 -> 推荐吃什么” | 首页 AI 助手、探索、详情 | Agent 推荐有事件流，菜谱来自后端 |
| R3 采购用户 | 验证多菜谱清单合并 | 清单导出、历史、详情导出 | 数量合并、复制/导出可用 |
| R4 健康用户 | 验证营养和微量营养素 | 健康仪表盘、详情、营养分析 | 热量/蛋白/碳水/脂肪/微量营养素展示 |
| R5 视觉识别用户 | 验证拍照识别、品质、向导 | 拍照识别、品质鉴定、探店向导 | 有图才识别，VLM 不可用时明确失败 |
| R6 答辩演示者 | 验证现场演示顺序和容错 | 全流程 | 3 分钟内能讲完主线，出错有备选路径 |

## 3. 总体验收标准

### 3.1 主链路必须通过

以下 4 条必须通过，否则答辩主线不稳：

1. 手机端首页能打开，底部导航/主要入口不缺失。
2. AI 助手输入自然语言后，能显示 Agent 事件流。
3. 推荐菜谱不为空，并包含匹配度、热量、时间或推荐理由。
4. 购物清单能由推荐菜谱导出或合并。

### 3.2 关键失败判定

以下任一情况应判为高优先级问题：

| 现象 | 严重程度 | 原因 |
|---|---|---|
| 手机端显示网络异常 | P0 | 主链路不可用 |
| AI 助手只有一句回复，没有过程 | P1 | Agent 可观测性缺失 |
| VLM 不可用却返回固定 mock 食材 | P0 | 数据真实性问题 |
| 推荐结果为空或全是前端 mock | P0 | 后端推荐链路未通 |
| 购物清单没有数量或无法复制/导出 | P1 | T 执行链路不完整 |
| 收藏/评分点击后 UI 不变化 | P1 | E 反馈体验失败 |
| 底部导航、设置页、历史页消失 | P1 | UI 功能回归 |
| 手机端按钮错位、文字遮挡 | P2 | 展示质量问题 |

## 4. R1 新用户测试

### 4.1 注册/登录

**目标**：验证手机端能建立用户身份，后续偏好和反馈有用户上下文。

**步骤**

1. 打开手机端 ByteSavor。
2. 如果未登录，进入登录/注册页。
3. 使用测试账号登录，例如：

```text
账号：te
或当前前端允许的 demo 账号
```

4. 登录后返回首页。

**预期结果**

- 页面不再停留在登录页。
- 首页能读取用户状态。
- 设置/我的页面可以打开。
- 刷新或重新进入后，登录态不应立即丢失。

**失败记录**

```text
账号：
是否出现网络异常：
是否返回首页：
是否能进入设置：
截图：
```

### 4.2 设置偏好

**目标**：验证用户画像能影响推荐。

**步骤**

1. 进入设置页。
2. 设置健康目标为“减脂”。
3. 设置偏好为“高蛋白”“辣味”或类似选项。
4. 保存。
5. 返回首页。

**预期结果**

- 设置项能被勾选。
- 保存后没有报错。
- 再次进入设置页，偏好仍然存在。
- 后续推荐中可能出现 `PREF_MATCH` 或“符合偏好”的理由。

## 5. R2 做饭用户测试：Agent 推荐主线

这是最重要的答辩主线。

### 5.1 自然语言推荐

**目标**：验证 Y 决策链路和 Agent 事件流。

**输入**

```text
牛肉南瓜减脂30分钟，推荐一道菜
```

**步骤**

1. 打开首页。
2. 找到 AI 助手输入框。
3. 输入上面的句子。
4. 点击发送。
5. 等待返回。

**预期结果**

页面应出现：

- 用户消息气泡。
- AI 回复。
- Agent 过程时间线，至少包含以下类型中的多个：

```text
规划下一步
调用工具
推荐完成
Agent 完成
```

推荐结果应满足：

- 菜谱列表非空。
- 至少 1 个菜谱与牛肉或南瓜相关。
- 有时间、热量、匹配度或推荐理由。
- 推荐不是静态固定卡片。

**后端数据预期**

Agent API 应返回类似：

```json
{
  "events": [
    {"type": "plan", "tool": "decision"},
    {"type": "tool_start", "tool": "decision"},
    {"type": "tool_result", "tool": "decision"},
    {"type": "final"}
  ],
  "recipes": []
}
```

**失败判定**

- 只有“AI Agent 暂未连通”。
- 只有一句回复，没有 Agent 时间线。
- 推荐为空。
- 页面显示旧的固定三阶段但没有新事件流。
- 后端日志没有收到 `/v1/agent/execute`。

### 5.2 多轮上下文

**目标**：验证 Agent 不是一次性 API，而是能复用会话上下文。

**前置条件**

先完成 5.1，自然语言推荐已经返回菜谱。

**输入**

```text
把刚才的菜生成购物清单
```

**预期结果**

- Agent 不应要求重新输入牛肉南瓜。
- 应复用上一轮推荐菜谱。
- 应调用清单相关工具或进入清单导出页面。
- 返回购物清单或提供导出入口。

**失败判定**

- 完全忘记上一轮推荐。
- 要求用户重新选择菜谱。
- 购物清单为空。
- 出现 JavaScript 报错或页面卡死。

### 5.3 探索模式

**目标**：验证用户没有明确食材时也能浏览推荐。

**步骤**

1. 进入“探索菜谱”页。
2. 查看菜谱卡片数量。
3. 点击任意菜谱进入详情。
4. 返回探索页。

**预期结果**

- 菜谱数量不能太少。
- 卡片有标题、热量、时间、标签或匹配信息。
- 详情页有步骤、营养、微量营养素。
- 返回后页面状态正常。

## 6. R3 采购用户测试：清单导出

结合 demo 场景二：

```text
demo_tests/场景二_清单导出/测试菜品.txt
```

测试菜品：

```text
豉汁石斑
xo酱西芹炒虾球
小炒黄牛肉
炝炒洋瓜尖
红三剁
莫式鸡煲
```

### 6.1 从推荐导出清单

**目标**：验证推荐菜谱可以进入 T 执行链路。

**步骤**

1. 在首页完成一次推荐。
2. 点击推荐卡片上的“记录”或“导出”。
3. 进入清单导出页。
4. 查看合并后的食材列表。

**预期结果**

- 清单页能打开。
- 食材列表非空。
- 每项至少有食材名。
- 有数量时显示数量和单位。
- 有挑选建议时应展示建议。

**重点检查**

```text
牛肉 300g + 400g -> 700g
整数不显示 700.0g
不同单位不要错误合并
适量/少许不要错误相加
```

### 6.2 复制到剪贴板

**目标**：验证导出能力，不只是展示。

**步骤**

1. 在清单导出页点击“复制到剪贴板”。
2. 打开手机备忘录或输入框。
3. 粘贴。

**预期结果**

- 出现复制成功提示。
- 粘贴内容包含食材名和数量。
- Markdown 或文本格式可读。

**失败判定**

- 点击无反应。
- 提示成功但剪贴板为空。
- 复制内容缺少数量。
- 微信小程序/H5 权限导致失败但没有提示。

### 6.3 编辑和勾选

**目标**：验证清单是可用工具，而不是静态展示页。

**步骤**

1. 勾选一个食材。
2. 删除或编辑一个食材。
3. 再复制一次清单。

**预期结果**

- 勾选状态可见。
- 删除/编辑后列表更新。
- 导出内容反映最新列表。

如果 VLM 不可用：

- 应显示明确失败。
- 不应返回固定 mock 餐食。

## 9. R6 答辩演示者测试

### 9.1 三分钟主线演示

建议现场只演示一条最稳主线：

2. 输入：

```text
牛肉南瓜减脂30分钟，推荐一道菜
```

3. 指出 Agent 时间线：

```text
规划下一步 -> 调用工具 -> 推荐完成 -> Agent 完成
```

```text
把刚才的菜生成购物清单
```

6. 展示清单合并和导出。

### 9.3 现场兜底话术

如果 VLM 不可用：

```text
视觉模型依赖外部服务。当前系统不会把 mock 数据伪装成真实识别结果，因此模型不可用时会明确返回错误。为了保证演示连续，我先展示不依赖视觉模型的自然语言 Agent 推荐链路。
```

如果网络异常：

```text
手机端访问本地后端需要处于同一局域网，并配置电脑 IP。这里先切换到浏览器/H5 或 Swagger 展示同一接口链路。
```

如果 Agent 只返回推荐但没有清单：

```text
第一轮是推荐任务，第二轮输入“把刚才的菜生成购物清单”会触发 task 工具，体现多轮上下文。
```


## 首页推荐卡

### 修改前问题

推荐卡主要展示标题、时间、热量、匹配分和简单 reason。后端已经返回了 `_meta` 等解释字段，但前端没有充分展示。

### 修改后逻辑

新增 `recipeExplainChips(recipe)`，优雅读取以下字段：

- `recipe._meta.matched_ingredients`
- `recipe._meta.missing_ingredients`
- `recipe._meta.purchase_suggestions`
- `recipe._meta.preference_matches`
- `recipe.llm_reranked`

字段不存在时隐藏，不报错。

展示文案示例：

- `已用 牛肉、韭黄`
- `缺 鸡蛋`
- `补买 鸡蛋 2个`
- `偏好 少油、减脂`
- `AI重排`

## AI 助手 Agent 时间线

### 修改前问题

时间线已有基础 `event.type` 展示，但没有充分体现 v6 后端事件字段：

- `planner_source`
- `candidate_tools`
- `skill.category`
- `retry_count`
- `cache_hit`
- `soft_judge`

### 修改后逻辑

`agentEventTitle(event)` 新增：

- `plan` 展示 planner source：规则 / LLM / 规则回退。
- `tool_result` 展示 skill category：感知 / 决策 / 任务 / 记忆。
- `soft_judge` 展示软评审结果：通过 / 提醒 / 跳过。

`agentEventDetail(event)` 新增：

- `plan` 展示候选工具和 LLM reason。
- `tool_result` 展示识别数量、推荐数量、清单数量、缓存命中、retry、error_code。
- `soft_judge` 展示 scores 和 issues。

## AI 助手推荐结果卡

### 修改前问题

AI 助手返回的菜谱只展示标题、匹配分、时间、热量。

### 修改后逻辑

每个 AI 推荐菜谱卡也复用 `recipeExplainChips(recipe)`，展示：

- 已匹配食材；
- 缺失食材；
- 补买建议；
- 偏好命中；
- AI 重排标识。

## 菜谱库卡片

### 修改前问题

菜谱库搜索和列表能够展示菜谱，但搜索/偏好融合后的解释信息没有展示入口。

### 修改后逻辑

`explore.vue` 新增 `recipeExplainChips(item)`，读取：

- `_meta.missing_ingredients`
- `_meta.purchase_suggestions`

- `llm_reranked`

## 手工验收建议

后续用真实浏览器或手机重点检查：

1. 首页输入 `牛肉韭黄`，推荐卡能看到 `已用/缺/补买/偏好/AI重排` 中至少一种解释标签。
2. AI 助手输入 `牛肉韭黄减脂30分钟`，时间线能看到 planner、skill、evaluation、soft judge。
3. 如果后端返回 `planner_source=llm`，前端能显示 LLM；如果 fallback，显示规则回退。
4. VLM cache 命中时识别页显示缓存和耗时。
5. 菜谱库搜索 `韭黄炒蛋` 仍能命中 `韭黄炒鸡蛋`。
6. 菜谱库卡片收藏、清点、计划按钮仍可点击。
7. 移动端宽度下解释标签不横向溢出。
8. 底部 tab 图标大小位置保持一致。

## 剩余风险

- 本轮使用静态 smoke 和 H5 build 验证，尚未用真实浏览器逐页截图检查 UI 视觉细节。
- `preference_matches`、`purchase_suggestions` 的展示依赖后端是否返回对应字段；字段不存在时前端会隐藏。
- Agent 时间线现在能展示 soft judge，但 soft judge 默认关闭，演示时需要确认后端配置开关。

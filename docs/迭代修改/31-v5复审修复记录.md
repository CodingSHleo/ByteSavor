## 1. 本轮复审发现的问题

### P0-1 密码注册会触发 MySQL 外键失败

文件：`app/services/user.py`

问题：

`create_password_user()` 中先 `db.add(user)`，随后直接 `db.add(Profile(user_id=user.id))` 并 `commit()`。在当前 SQLAlchemy/MySQL flush 顺序下，`profiles` 可能先插入，导致：

```text
Cannot add or update a child row: a foreign key constraint fails (`profiles`, FOREIGN KEY (`user_id`) REFERENCES `users` (`id`))
```

影响：

- 密码注册路径不可用。
- subagent 报告里的“账号登录全部完成”不成立。

修复：

```python
db.add(user)
await db.flush()
profile = Profile(user_id=user.id)
db.add(profile)
```

### P0-2 密码登录对空/坏 password_hash 不防御

文件：`app/services/user.py`

问题：

旧 OpenID 用户或异常数据可能存在空 `password_hash`。原逻辑直接：

```python
verify_password(password, user.password_hash or "")
```

`bcrypt.checkpw()` 遇到空 hash 可能抛 `ValueError: Invalid salt`，会把普通登录失败变成 500。

修复：

- 空 `password_hash` 直接返回 `None`。
- `verify_password()` 外层捕获 `ValueError`，统一返回登录失败。

检查：

```bash
JWT_SECRET=test-review-secret /Users/liwenbin930/Desktop/bytesavor-backend/venv/bin/python -m pytest -q tests/test_auth.py
```

专项已包含在本轮 DB 复核里：`26 passed`

### P1-1 用户表运行时迁移没有补齐唯一索引

文件：`app/services/user.py`

问题：

`User` ORM 上声明了：

```python
username = Column(String(64), unique=True, nullable=True, index=True)
email = Column(String(120), unique=True, nullable=True, index=True)
```

但 MySQL 已有表不会因为 `Base.metadata.create_all()` 自动新增唯一索引。原 `ensure_user_auth_columns()` 只补字段，不补索引，真实数据库层面可能允许重复 `username/email`。

修复：

在 `ensure_user_auth_columns()` 中幂等检查并创建：

```sql
CREATE UNIQUE INDEX uq_users_username ON users (username)
CREATE UNIQUE INDEX uq_users_email ON users (email)
```

同时把 `openid` nullable 修改改成先查 `IS_NULLABLE`，避免每次启动/登录都无条件 `ALTER TABLE users MODIFY COLUMN openid ...`。

检查：

```bash
./scripts/verify_db.sh
```

结果：`39 passed`

### P1-2 社区空评论被 Pydantic 拦成 422，破坏统一错误语义

文件：`app/routers/community.py`

问题：

`CommentRequest.content` 使用 `min_length=1`，空评论会在 FastAPI/Pydantic 层直接返回 422，不走项目统一的：

```json
{"status":"error","error":{"code":"INVALID_COMMENT"}}
```

这和 v5 任务书及现有测试要求不一致。

修复：

去掉 schema 层 `min_length=1`，交给 `community.add_comment()` 做业务校验并返回 `ErrorResponse(code="INVALID_COMMENT")`。

检查：

```bash

```

专项已包含在本轮 DB 复核里：`26 passed`

## 4. 给后续 subagent 的检查要求

后续继续接手时，不允许只贴“全部完成”表格，必须按下面方式交付。

### 4.1 必须给出真实命令

至少包含：

```bash
./scripts/verify_quick.sh
./scripts/verify_db.sh
```

涉及 API Eval 时再加：

```bash
./scripts/verify_eval_api.sh
```

### 4.2 必须区分三种结果

- 普通沙箱不可访问 MySQL：说明为环境权限问题，不要写成测试失败。
- MySQL 环境下断言失败：必须修代码。
- H5 build 通过：只能说明编译通过，不等于前端交互人工验收通过。

### 4.3 前端任务不能只改 API

如果任务书写了“页面 loading/error/empty/删除入口/点赞状态/加载更多”，必须检查 `.vue` 页面是否真的实现，不允许只改后端或 `ApiService`。
